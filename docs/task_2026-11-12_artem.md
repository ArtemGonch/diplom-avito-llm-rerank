На 12.11 последняя запись в рабочем документе — итог от 29.10, последнее назначенное задание — от 22.10. Новых выгрузок в проверенных папках диплома не найдено. Ниже — собственные следующие шаги, а не новое назначение от Ромы.

1. Проверить на текущей истории, предсказывают ли прошлые фильтры следующий поиск, и сравнить личные сигналы с общим фоном. Выполнено.
2. Подготовить воспроизводимый подсчёт независимых слепых оценок саммари. Обработка готова; эксперты ещё не выставили оценки.
3. Подготовить минимальный контракт выгрузки для оценки NDCG и проверку формата до запуска. Контракт и проверка готовы; испытание на данных Ромы ожидается.

## Временная проверка поиска

Использован проверенный по манифесту октябрьский экспорт 100 пользователей. Когорта отобрана 20.09, после отсечки, поэтому это ретроспективная проверка на фиксированной когорте, а не оценка для всех пользователей на момент прогноза. Разбиение по середине наблюдаемого периода: до 13.09.2026 00:00 по часам источника — история, начиная с этой отсечки — будущее. Для пользователя берётся **первый зарегистрированный момент поиска** после отсечки. Если этот момент не сопоставлен однозначно или в нём нет подходящих однозначных значений, более поздний поиск не подставляется.

Проверяем точное совпадение значений пяти напрямую записанных полей: марка, коробка, тип двигателя, привод, регион бренда. Учитываем только поля с одним явным значением в целевом запросе. Поэтому это диагностика **значения заданного фильтра**, а не предсказание, какой фильтр вообще будет указан. Используем только исходные параметры поиска: ни полные саммари, ни будущие карточки, ни признаки объявления в прогноз не входят. Одинаковые прошлые временные отметки объединяются; если при этом несколько значений, такой момент не даёт голос за одиночное значение. Поля не образуют составной прогноз целого запроса.

- **Последнее явное значение:** на каждый атрибут отдельное последнее наблюдение; при нескольких значениях в нём правило воздерживается.
- **Мода по дням:** один голос на значение в день, совпадающие повторы не добавляют голосов. Ничья — воздержание.
- **Согласие:** ответ только если оба личных правила дали одинаковое значение.
- **Общий фон:** самое популярное одиночное значение среди остальных пользователей до той же отсечки, максимум один голос на значение от каждого. Текущий пользователь исключён, ничья — воздержание.

У 48 пользователей нет будущего поиска, ещё у 20 первый поиск не даёт одиночного значения по выбранным полям. Осталось **32 пользователя и 46 проверяемых значений**, в том числе 12 пользователей без сопоставленной истории до отсечки. По всем 46 значениям последнее значение угадало **10 из 23 прогнозов**, мода по дням — **9 из 17**, согласие — **8 из 16**, общий фон — **14 из 46**. Остальные значения для каждого метода — воздержания. Общий фон покрыл больше случаев и дал больше совпадений по всей выборке, хотя доля совпадений среди его ответов ниже.

На одном наборе, где могли ответить обе личные эвристики и общий фон (17 значений у 13 пользователей), точность с одинаковым весом пользователей: последнее значение **53,8%**, мода **61,5%**, фон **36,5%**. Это малый отобранный срез, а не преимущество метода на всей когорте. Когда проекция будущего запроса на пять полей не повторяла прошлую, последнее значение совпало **3 раза из 14 прогнозов** (37 целевых значений). Разбиение на повтор и новизну использует будущий запрос только для анализа результата; это не правило маршрутизации при запуске.

Практическое решение: сохранять исторический профиль как слабую подсказку и тестировать его добавку к базовому порядку; текущие явные условия должны иметь приоритет. Консенсус двух личных правил пока не даёт основания включать более жёсткий порог: он уменьшил покрытие и не улучшил долю совпадений против моды. Это диагностический прогон на одной малой выборке, без вывода о покупке, пользе LLM или качестве ранжирования. См. [агрегаты](../results/current/metrics/avito_search_holdout_20261112.json).

## Слепая оценка саммари

`annotations` принимает CSV из существующего слепого интерфейса (один экспорт на эксперта) и закрытый ключ из **той же сборки**. Ответы A/B раскрываются только при подсчёте, сравнения с priority и diverse не смешиваются. Пропуск, «не хватает оснований» и ничья обрабатываются по-разному. Дубликаты внутри CSV, неверные идентификаторы, значения и столбцы отклоняются. По каждому пользователю сначала усредняются оценки экспертов, затем пользователи имеют одинаковый вес. Для шкал 1–5 используются только пары с обеими оценками; согласие для пользователей с несколькими ответами считается отдельно по предпочтениям. Итог не содержит построчных ответов, ключа, заметок или идентификаторов.

Существующий пустой шаблон проверен: ноль голосов, средние отсутствуют. Это проверка обработки, а не результат опроса. CSV старого формата не содержит отпечатка пакета, поэтому команда требует явного подтверждения `--confirm-same-bundle`. Координатор указывает одну уникальную метку на эксперта и один его итоговый CSV. Исходный ключ и сырые ответы не публиковать.

## Минимальная выгрузка от Ромы

Для первого командного прогона достаточно одной выборки реальных выдач: ID запроса и пользователя, время и условия, **весь** показанный пул ID объявлений с исходными позициями, раздельно клики и целевые контакты и границы окна атрибуции. Для личных признаков — история до показа и пригодные на то время атрибуты. Для сравнения именно с командным CatBoost, а не с порядком в логе, нужны его оценки или ранги на тех же запросах и кандидатах. Фото, описания и саммари коммуникаций можно дослать второй очередью, с ключами соединения и временем доступности. См. [формат входа](avito_serp_intake.md).
