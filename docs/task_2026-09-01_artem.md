# Задание 2026-09-01: браузер кейсов Avito

Источник: командный [Google-документ](https://docs.google.com/document/d/1RIM-1r5kKr_rC7uFQa-m6iaht65K7R0-plInyvwA0XI/edit?tab=t.0),
повторно прочитан через публичный text export **2026-09-08**.

## Исходная формулировка

Цель:

- собрать интерфейс, в котором можно посмотреть историю пользователя
  (контакты), выдачу, ранжирование LLM и реальные контакты по выдаче;
- найти интересные кейсы;
- проверить, что полезного LLM может сообщить про объявление и пользователя
  по его истории.

Для этого нужно:

- пошарить айтемы через Google Drive — Артём;
- Роме дослать картинки и описания по айтемам;
- написать интерфейс;
- отладить интерфейс, чтобы кейсы было удобно смотреть.

## План выполнения

1. Зафиксировать контракт данных и разделить rank-time признаки, benchmark
   relevance и post-exposure события.
2. На одном неизменном test split соединить объявления с локальными score
   artifacts CatBoost, Qwen L0 и отклонённого gate.
3. Построить self-contained интерфейс без серверных зависимостей: история,
   карточки выдачи, переключение методов, релевантность и фактический TC-event.
4. Автоматически выбрать контрастные кейсы по per-SERP метрикам, а не вручную.
5. Сгенерировать Qwen-инсайты про объявления и историю; валидировать язык,
   схему, evidence и безопасность, не допуская target leakage.
6. Сформировать два списка `item_id` для Ромы: приоритетные featured items и
   полный test split; предусмотреть overlay для текста и изображений.
7. Собрать переносимый ZIP для расшаривания и описать запуск/ограничения.
8. Прогнать unit/integration проверки, сверить метрики и провести независимое
   ревью до отсутствия замечаний.
