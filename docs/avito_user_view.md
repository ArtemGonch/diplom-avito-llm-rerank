## Поисковые состояния и явные предпочтения

Из 1 998 событий 1 986 matched, 12 ambiguous. Повторы страниц и порядка значений
не повышают поддержку: одинаковые состояния доступных фильтров объединяются.
Поддержка показана как states/events/days, с первичными search references.
Это не доказанный session ID. Неподдерживаемые поля могут не различать состояния,
поэтому число 572 не называется числом всех исходных сессий/намерений.

Typed mapping: brand `110000`, model `110001`, generation `110005`, transmission
`110008`, engine type `110006`, drive `110007`, brand region `152642`;
кузов/двери `147411` сохраняются совместными вариантами. Год `164669`, пробег
`2687`, мощность `110011`, объём запроса `162396` читаются как диапазоны.
Цена — только из точных читаемых строк `Цена от … ₽`/`Цена до … ₽`.

Нули unset-границ, домены и противоречия проверяются. Год `201` и объём `331815`
не становятся допустимыми ограничениями. У ambiguous searches нет приписанных
фильтров. Для подбора берётся последняя matched-конфигурация, **включая пустую**:
поздний поиск без фильтров сбрасывает прежние ограничения. Более поздний
ambiguous поиск означает непроверенный текущий контекст.

Регион бренда задан у 12 профилей. Это явное условие запроса, а не восстановленная
страна производства объявления. Для проверки региона каждого кандидата нужен
отдельный справочник. Читаемые ограничения владельцев не сопоставляются с
listing-кодами по догадке.

## Описательная важность и числовые диапазоны

Базовая концентрация: ≥5 известных объявлений, заполненность ≥60%; одно
значение ≥70% либо два ≥85% суммарно, второе ≥20%.

Фон — уникальные объявления остальных пользователей, текущий пользователь
исключён. Для повторных item выбирается детерминированный представитель по
дате источника цены и tie-break; это ретроспективный пул. При ≥20 известных
фоновых значениях отличительный сигнал требует разницы долей ≥20 п.п. и
Wilson lower bound (z=1.96) выше фоновой доли. Это **описательный фильтр**, не
тест статистической значимости: независимость наблюдений/случайность выборки
не доказаны. Общий для когорты бензин не объявляется личным ключевым фактором.
Явный фильтр получает отдельный приоритет, но исторические observed values и
значения в поисках не подменяют друг друга.

Скоринг приоритета: для explicit `1 + states_with_field / all_states`, иначе
`max(0, WilsonLower - background_share) × coverage`. Это правило сортировки
исследовательских сигналов; причинная важность не обучалась. При малом фоне
сохраняется обычная концентрация с соответствующим статусом. Вариативность
не доказывает неважности параметра.

Числовая полоса — кратчайший наблюдаемый интервал с ≥ceil(0.8×n) известными
значениями; ties разрешаются по близости центра к медиане и порядку. Показаны
полный разброс и p10/p90 отдельно. При n≥5 и coverage≥60% «узкий» означает:
цена — ширина/медиана ≤0.4; год — ширина ≤4; пробег — ≤50 000 км и relative≤0.6;
мощность — ≤40 л.с. и relative≤0.3; объём — ≤0.5 л. Это фиксированные эвристики.
Один дорогой объект не обязан растягивать основной 80%-интервал.

Для model-common требуются ≥3 известных объявления модели, coverage≥60%,
доля свойства ≥70%; общее между моделями выводится при ≥2 таких моделях и
согласии ≥70%. Одинаковые названия разных брендов не объединяются.

## Группы и альтернативы

Группы — кузов × КПП, соседний разрыв цены >1.8× начинает новую полосу;
показываются группы ≥3, пары, singletons и записи без полей группировки.
Крупнейшая группа не называется доминирующей без ≥5 объявлений и ≥50% всей
анализируемой истории. При равенстве размеров уникального primary нет.
Результат воспроизводим, но не называется обученной latent кластеризацией.

Для альтернатив рассматриваются до трёх наблюдаемых сценариев. Ограничения
последней matched-конфигурации заменяют соответствующие observed defaults;
внутри поля варианты OR, между полями AND, body/doors проверяются совместно.
Никаких составных запросов из разных поисковых состояний. Исторические
engine/drive концентрации ≥80% могут задавать defaults, если запрос их не меняет.

Без явного диапазона используются цена p10×0.8…p90×1.2 и год p10−3…p90+3
сценария. Исключены все seen item IDs и seen brand/model пары, включая client-only.
Ранжирование примеров — log-price distance плюс штраф за непроверяемые поля,
детерминированные tie-breaks. Это эвристика гипотез, не рекомендательная метрика.

Условные примеры с неизвестными region/owners/другими полями имеют отдельный
список `unverified`. Доступные противоречащие значения отклоняются. При плохих
последних ограничениях или отсутствии совпадений причина показана явно.
Выдаётся до шести моделей с конкретным source snapshot. Полнота каталога,
доступность и полезность пользователю не доказаны.

## Саммари и LLM-редактор

Код строит полный fact store по всем разделам задания: текст, rule version,
item/search references, candidate reference и hash. Полный текст доступен для
100/100 профилей, в том числе 21 без карточек. У двух пустых профилей есть поиски;
«нет карточек» не заменяется утверждением «нет интереса».

Два агента текущей LLM-сессии индивидуально прочитали каталог и отобрали 515
фактов для коротких обзоров 100 профилей. Профиль 026 перечитан после исправления
сброса фильтров; новая выборка и hash сохранены. Это **LLM-отбор фактов**, а не
свободная генерация новых сведений, Qwen-run или обучение. Model revision текущей
сессии не предоставляется инструментом, поэтому записано `not_exposed`, а не
придуманная версия. Отдельная GPU-машина при проверке была недоступна по SSH;
переноса приватной выгрузки на новые внешние сервисы не было.

Cache принимает только ordinal user_index, точный fact_hash и список известных
fact IDs. Произвольный текст, новые значения/поля, чужие evidence, stale hash,
дубли и неизвестные IDs отклоняются. Показываются только canonical sentences.
Граница доверия: **fresh build из проверенных источников**, не импорт произвольных
precomputed analyses. Validator сверяет derived fact store с текущими вычислениями,
но не является независимым криптографическим доказательством первичных данных.
Без cache обзор честно помечается rules; частичный cache не даёт claim 100/100.

## Расширение v3 — задание 22.10, выполнено 29.10.2026

Новый модуль `src/avito_user_view/research.py` добавляет отдельный research-слой.
Версия сборки/аудита — `user-summary-v3`, canonical facts по-прежнему v2:
все 100 hashes и исходные 515 LLM-selections сохранены. Это повторное
использование замороженного выбора 22 октября, не новые вызовы модели.

**Ведущий атрибут.** Сначала исторические явные фильтры: доля уникальных
поддерживаемых конфигураций, где атрибут задан. Значения и числовые диапазоны
восстанавливаются по отдельным состояниям; разные поиски не превращаются
в один составной запрос. Повторные страницы не увеличивают поддержку.
Все максимумы с равным score сохраняются. Без явных фильтров допустим только
имеющийся отличительный сигнал относительно LOO-фона; обычная концентрация
не вынуждает выбрать лидера. Это описательный приоритет за период истории,
не причинная/статистическая значимость и не текущий набор ограничений.

**ДИ медианы.** Для каждого из четырёх полей берутся уникальные анализируемые
объявления с допустимым известным значением. Противоречащие значения дубля
исключаются. Endpoint показывается при n≥10 и known/analyzed≥60%.
Точный консервативный sign/order-statistic интервал выбирает наибольшее k,
для которого `2 P[Bin(n, 0.5) ≤ k−1] ≤ 0.05`, затем
`[x_(k), x_(n−k+1)]` (ранги с единицы). Биномиальные суммы вычисляются
целыми числами, включая длинные истории без underflow.
При n≤5 нет конечного двустороннего 95%-интервала этого вида.

Оцениваем гипотетическую медиану распределения аналогично наблюдаемых
объявлений: медиана конечной выгрузки уже известна точно. Номинальная
вероятностная гарантия требует IID; модель отбора просмотров не проверена.
Это исследовательская постановка для обсуждения, не доказанный доверительный
интервал истинного предпочтения, бюджета, будущей покупки или рекомендаций.
Пропуски/поздние snapshots остаются. Четыре отдельных 95% не дают совместных
95%. Повторы значений могут дать нулевую ширину без гарантии знания интереса.
После адаптивной кластеризации ДИ не строятся из-за post-selection.
80%-полоса наблюдений остаётся отдельным описательным показателем.

**Чувствительность.** При ≥3 календарных днях сопоставленных поисков удаляем
каждый день, оставляем состояния с событиями в другие дни и пересчитываем
ведущие явные атрибуты. Сравниваем множества атрибутов, не их значения.
Невалидные даты/короткая история не получают оценки; повторы одного состояния
в нескольких днях сохраняются после удаления только одного дня.

**LLM и правила.** Один canonical catalog, одинаковое число содержательных
фактов K. Общие ограничения по общению/стране/времени показаны всем методам
вне K. Priority сортирует по `(-priority, id)`; diverse берёт разные разделы,
затем заполняет оставшийся бюджет по приоритету. В сумме K=489 для каждого
метода против 515 исходных LLM-facts. Отчёт показывает символы, разделы и
Жаккар; это diagnostics, не независимые оценки качества. Длина не выровнена
по tokens/символам. Полезность и NDCG пока не измерены.

**Слепые пакеты.** `annotation_priority.zip` и `annotation_diverse.zip`
