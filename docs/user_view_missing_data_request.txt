Рома, привет! По заданию от 16.10 собрали user-view и саммари для 100 пользователей из пакета usedcars-100-no-communications-2026-10-16. Ниже отдельно то, чего не хватает для оставшихся выводов и проверки гипотез.

1. Для обязательного пункта про темы вопросов — содержание коммуникаций.
Нужны доступные для исследования обезличенные тексты чатов либо транскрипции звонков за 6–19 сентября по этой когорте. Минимальные поля: стабильный псевдоним user_id, item_id, conversation_id, message_id/порядок реплики, timestamp с часовым поясом, роль покупатель/продавец, текст. Указать, какие каналы и пользователи покрыты, а какие отсутствуют. Личные контакты, имена, телефоны, адреса и VIN для анализа тем не нужны. Нужна возможность отличить «не задавал вопрос» от «текст не выгружен». Факты контактов в текущем архиве есть, но содержания общения нет.

2. Для пункта «страна-производитель» — определение и справочник.
Нужно уточнить, что подразумеваем: происхождение бренда или страну производства/сборки конкретного автомобиля. В запросах уже есть «Регион бренда» (152642), его мы показываем именно как явный фильтр. В карточках проверенного соответствия этому региону нет. Если достаточно страны/региона бренда — нужен версионированный справочник brand -> country/brand_region с источником и правилами для международных брендов. Если нужна сборка — отдельное достоверное поле на уровне объявления/автомобиля, с источником и датой. Эти понятия не будем смешивать.

3. Для более полного подбора новых моделей — каталог за пределами историй.
Нужен список кандидатов или справочник моделей с brand/model/generation, кузовом, дверями, КПП, типом двигателя, приводом, годом, ценой, пробегом, мощностью, объёмом и регионом бренда. Для объявлений — item_id, дата снимка и интервалы активности/доступности. Сейчас новые модели подбираются только из историй остальных пользователей сэмпла; полноту каталога и наличие на конкретную дату проверить нельзя. Дополнительно нужна расшифровка listing-кодов числа владельцев (параметр 1167): в запросах значения читаемые, а справочника кодов карточек нет.

4. Для проверки фразы «ему зайдёт» — независимый результат после подбора.
Желательны последующие просмотры/избранное/контакты по этой когорте после 19 сентября, с датами и описанием покрытия. Либо небольшой протокол экспертной разметки предложенных моделей. Без этого текущий список — обоснованные гипотезы, а не измеренное качество рекомендаций. Это не препятствует просмотру саммари на имеющихся данных.

5. Для строгого восстановления на момент действия — временной контракт.
Нужны время события/запроса/показа и часовой пояс, ревизии цены и параметров с полными интервалами действия, определение включённости from/to и доступности полей. Большая часть нынешних атрибутов — snapshot fallback; часть снимков позже действия. IMV сейчас является дневной ретроспективной оценкой. Для обучения/benchmark потребуется available_at для IMV и исходов; это отдельное требование, а не недостающий пункт интерфейса.

6. Необязательно для расчётов саммари, но полезно для user-view — фотографии.
Нужны сами файлы либо согласованный способ получить изображения по сохранённым image-storage ID, со связкой item_id и временем снимка. В текущем ZIP есть только ID, поэтому фотографии не отображаются.

Основная работа по доступным данным выполнена без ожидания этих выгрузок. Критически не закрыт именно анализ содержания общения; страна и внешняя проверка альтернатив требуют указанных уточнений. Самостоятельно тексты общения/страну/результат покупки не достраиваем.
