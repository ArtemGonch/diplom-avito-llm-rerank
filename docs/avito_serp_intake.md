# Avito: первый пакет для сравнения ранжирования

Для первого измерения NDCG достаточно одной выгрузки с фиксированным набором запросов. Формат ниже — **наш нормализованный вход**, исходные данные можно передать в удобном табличном виде и затем привести к этому формату.

- Запрос: псевдонимизированные ID запроса и пользователя, время показа с часовым поясом, запрос или фильтры, размер показанного пула, исходная позиция каждого объявления.
- Кандидат: псевдонимизированный ID объявления и раздельные признаки клика и целевого контакта. Нужны описание целевого события, окно атрибуции и подтверждение его полноты. `false` — наблюдали всё окно и события не было; `null` — неизвестно. Пропуски не заменять нулями.
- Для персонализации: события истории со временем, теми же ключами, сведениями о времени доступности атрибутов и контрактом строгой отсечки. События и сведения, ставшие доступны в момент показа или после, не идут в признаки.
- Для сравнения с командным CatBoost: оценки или однозначный порядок на **том же пуле**, правила обработки совпадений, принадлежность запроса к split. Позиция показа сама по себе означает логированный порядок.
- Опционально для следующего этапа: фото, тексты объявлений и саммари коммуникаций с теми же псевдонимизированными ключами и временем доступности. Их можно прислать отдельно.

Один JSON-объект на строку. Пример **синтетический**, поэтому идентификаторы и исходы не относятся к реальным событиям:

```json
{"request_id":"demo-1","user_id":"demo-user","shown_at":"2026-10-01T09:00:00+03:00","history_cutoff":"2026-10-01T09:00:00+03:00","query_context":{"filters":{"body":"sedan"}},"logged_size":2,"candidates":[{"item_id":"demo-a","position":1,"clicked":true,"target_contact":false},{"item_id":"demo-b","position":2,"clicked":false,"target_contact":null}]}
```

```bash
python scripts/avito/evaluate_user_view.py serp-preflight --input /path/to/private/serps.jsonl
```

Проверка отклоняет повторы запросов, дубликаты кандидатов, пропущенные или повторные позиции, несогласованный размер пула, недопустимые метки и временную границу после показа. В примере клики полностью наблюдались и есть положительная метка, а по целевым контактам запрос не готов из-за неизвестного исхода. Итог содержит только счётчики. Размер пула должен приходить из лога независимо от списка; формальная проверка не доказывает, что источник действительно прислал все показы. Проверка даты отсечки не проверяет историю построчно — её надо сверять при соединении признаков. Ранжирование здесь не запускается.

Перед запуском зафиксировать одинаковый пул кандидатов и тестовый отрезок для всех методов, клики и целевые контакты оценивать отдельно, запросы без положительной наблюдаемой метки и запросы с неизвестными метками учитывать отдельными счётчиками. Логированные клики подвержены эффекту позиции; офлайн NDCG не заменяет проверку онлайн.
